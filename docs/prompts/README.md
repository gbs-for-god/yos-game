# 프롬프트 기록

기능을 만들거나 고칠 때 **사용자가 보낸 요청 원문과 구현 결정**을 남기는 곳이다.
나중에 "이 기능이 왜 이렇게 동작하는지"를 되짚거나, 비슷한 기능을 요청할 때 참고하기 위해 쓴다.

## 규칙

- 파일 이름은 게임 slug와 같게: `docs/prompts/<slug>.md` (예: `number-draw.md`)
- 게임이 아닌 공용 기능은 기능 이름을 kebab-case로: `docs/prompts/score-board.md`
- 한 기능에 요청이 여러 번 오면 **같은 파일에 날짜 순으로 섹션을 덧붙인다** (최신이 아래)
- 요청 원문은 고치지 않고 그대로 붙인다. 해석·판단은 "구현 결정"에 적는다

## 템플릿

```markdown
# <게임/기능 이름> (`<slug>`)

## YYYY-MM-DD — <한 줄 요약>

### 요청 프롬프트

> 사용자가 보낸 요청 원문을 그대로 붙여 넣는다

### 구현 결정

- 규칙 해석, 선택한 방식과 이유
- 범위에서 뺀 것과 그 이유

### 변경 파일

- `games/<slug>/...`
- `e2e/<slug>.spec.ts`

### 검증

- `pnpm verify` 통과 여부
- 브라우저(1920×1080) 확인 여부
```
