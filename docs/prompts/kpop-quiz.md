## 2026-11-10 — 2008~2010 K-pop 앞부분 듣고 맞추기 (사회자 전용)

### 요청 프롬프트

> # K-pop 노래 맞추기 진행자용 웹 애플리케이션 개발 요청
>
> 2008~2010년 유행했던 K-pop 노래의 앞부분을 듣고 맞추는 레크리에이션 게임을 만들어줘.
>
> ### 1. 주요 요구사항 및 화면 구성
>
> - **진행자(Host) 전용 모드**:
>   - 사회자가 로그인이 되야만 진행할 수 있다.
>   - 진행자가 화면을 띄워두고 프로젝터/모니터 화면 공유나 현장 진행을 할 수 있는 직관적인 단일 대시보드 구조.
> - **블라인드 오디오 재생 (YouTube IFrame Player API)**:
>   - 정답 공개 전에는 참여자들에게 영상 화면, 썸네일, 영상 제목이 노출되지 않도록 화면을 완전히 블라인드(오디오 전용 플레이어 UI) 처리.
>   - 정답 공개 전에는 소리만 출력되어야 함.
> - **구간 듣기 및 오디오 컨트롤**:
>   - 재생, 일시정지, 이전 곡, 다음 곡 이동 버튼.
>   - 문제 출제용 간편 버튼: "앞부분 1초 듣기", "3초 듣기", "전체 재생" 기능 포함.
> - **정답 공개 기능**:
>   - [정답 공개] 버튼 클릭 시 블라인드가 해제되며 가수, 곡명, 앨범 커버 또는 유튜브 실제 영상 화면이 노출됨.
>
> ### 2. 데이터 구조 (Mock Data 포함)
>
> - 2008~2010년 대표 K-pop 5~10곡을 mock data(JSON)로 기본 포함해줘.
>   (예: 소녀시대 - Gee, 빅뱅 - 하루하루, 브라운아이드걸스 - Abracadabra, 2PM - Heartbeat, 원더걸스 - Nobody 등)
> - 데이터 모델 형식: `id`, `title`, `artist`, `youtubeId`, `startTime`(문제 재생 시작 지점, 초 단위, 기본 0초)
>
> ### 3. UI/UX 디자인 가이드
>
> - 어두운 환경(프로젝터 투사 등)에서도 가독성이 높은 모던한 다크 모드 스타일.
> - 직관적인 대형 버튼(재생/정지, 정답 공개)과 키보드 단축키(Space: 재생/정지, Enter: 정답 공개, 방향키: 이전/다음 곡) 지원.

### 구현 결정

- **"로그인" = 사회자 비밀번호**: 프로젝트에 계정 로그인이 없고(규칙 5) 사회자 구분은 `x-host-pin` 비밀번호뿐이라 이를 로그인으로 해석했다. 서버가 비밀번호를 확인한 뒤에만 대시보드를 보여 주고(`useVerifiedHostPin`), 로그인 전에는 곡 정보가 화면에 전혀 없다. 기억해 둔 비밀번호가 바뀌었으면(401) 자동 로그아웃. 비밀번호 폼은 `/host`와 같은 `HostPinForm`을 공용으로 뽑아 재사용했다.
- **서버 상태 없음**: 한 기기(사회자 노트북)에서만 쓰므로 Redis·API 추가 없이 클라이언트에서만 동작한다.
- **YouTube IFrame API**: 요청에 명시된 외부 API로 보고 공식 스크립트를 직접 로드한다(npm 패키지 추가 없음, `youtube.ts`에 최소 타입만 선언). 사회자가 로그인한 뒤에만 스크립트를 불러온다.
- **블라인드**: 플레이어(iframe)를 정상 크기로 두고 불투명 가리개(`blind-cover`)로 완전히 덮는다. 플레이어를 숨기거나 줄이면 재생이 막힐 수 있어서다. 공개 전에는 iframe 영역을 `aria-hidden`으로도 숨긴다. 플레이어 컨트롤·키보드·전체화면·관련 영상은 끈다(`controls=0`, `disablekb=1`, `fs=0`, `rel=0`).
- **정답 공개 시 실제 영상 노출**: 가리개만 치우면 같은 플레이어가 그대로 보인다(앨범 커버 대신 영상 선택).
- **구간 듣기**: 문제 시작 지점(`startTime`)으로 이동·재생한 뒤 `getCurrentTime()`을 50ms마다 확인해 N초에 일시정지한다(타이머로 N초 뒤에 멈추면 버퍼링 지연만큼 짧게 들린다). 전체 재생은 시작 지점부터 끝까지 계속 재생. 곡을 옮기면 자동 재생 없이 새 영상만 준비(cue)한다. 플레이어는 곡마다 새로 만들지 않는다.
- **곡 데이터**: 8곡(소녀시대 Gee, 원더걸스 Nobody, 빅뱅 하루하루, 브라운아이드걸스 Abracadabra, 2PM Heartbeat, 슈퍼주니어 쏘리 쏘리, 샤이니 링딩동, 2NE1 Fire). 영상 ID는 검색으로 찾고 유튜브 oEmbed로 존재·임베드 가능(200)을 확인했다. 링딩동은 공식 오디오 업로드, 하루하루·Abracadabra는 공식 채널이 아닌 업로드라 나중에 삭제될 수 있다. `startTime`은 모두 0으로 두었고 실제 인트로는 듣고 조정이 필요할 수 있다.
- **추가한 것**: 순서 섞기, 로그아웃, 재생 오류(임베드 금지·삭제) 사유 표시.
- **레이아웃**: 큰 화면에서는 무대·정답을 왼쪽, 조작 버튼을 오른쪽에 두어 1920×1080 한 화면에 모두 보이게 했다.
- **범위 밖**: 참여자 휴대폰 화면, 점수판, 서버 저장, 곡 편집 UI(`data/songs.json` 직접 수정).

## 2026-11-10 — 코러스 구간 재생 버튼 추가

### 요청 프롬프트

> 코러스 구간을 재생하는 버튼 추가

### 구현 결정

- **데이터**: 곡에 선택 필드 `chorusStart`(초)를 추가했다. 값이 없으면 버튼이 꺼진다(`validateSongs`가 음수는 거부).
- **버튼 동작**: "🎤 코러스 15초 듣기"는 코러스 시작 지점으로 이동해 15초(`CHORUS_SECONDS`)만 재생하고 멈춘다. 앞부분 듣기와 같은 구간 재생 코드(`playRange`)를 공유하고, 상태 문구는 "🔊 코러스 구간 듣는 중"으로 구분한다. 곡을 옮기면 그 곡의 코러스 지점을 쓴다.
- **코러스 지점 값은 추정치**: 소리를 직접 들어 확인할 수 없어, 곡 길이가 일치하는 원곡 동기화 가사(LRCLIB 공개 API)에서 **반복되는 6줄 블록의 첫 등장 시점**을 계산하고 0.5초 앞당겼다. 가사 자체는 저장하지 않고 계산된 시간만 데이터에 넣었다. 유튜브 "가장 많이 재생된 장면"과 교차 확인했을 때 Gee(59초)·Nobody(58초)·하루하루(76초)·Heartbeat(74초)는 정점과 겹쳤고, 나머지(Abracadabra 30초·쏘리 쏘리 15초·링딩동 69초·Fire 17초)는 근거가 약하다. 쏘리 쏘리(15초)와 Fire(17초)는 코러스가 아니라 앞부분 후크/프리코러스일 수 있다. 실제 음원과 가사 파일의 길이가 1~2초 어긋나는 곡(Nobody, 링딩동, Fire)은 시점이 그만큼 밀릴 수 있다.

## 2026-11-10 — 공개한 정답 유지 + 사회자 메뉴에서 게임 초기화

### 요청 프롬프트

> 1. 음악 맞추기 게임에서 "정답 공개" 버튼을 클릭하면 그 문제는 계속 공개된 상태로 유지
> 2. 사회자 메뉴에서 음악 맞추기 게임 초기화 버튼을 클릭하면, 정답이 공개된 문제들을 다시 원상 복구하고 순서를 한 번 섞어

### 구현 결정

- **"계속 공개"의 범위**: 곡을 옮겼다 돌아와도, 새로고침·브라우저 재시작 후에도 공개 상태로 남도록 해석했다. 곡마다 공개 여부를 따로 기억한다(공개 안 한 곡은 계속 가려진 채). 이전에는 곡을 옮기면 가렸다.
- **저장 위치**: 이 기기의 `localStorage`(`yos-game:kpop-quiz:state` — 곡 순서 id, 현재 곡 번호, 공개한 곡 id). 서버는 쓰지 않는다. 곡 정보는 `songs.json`이 원본이라 id만 저장하고, 복원할 때 곡 목록이 바뀌었으면(삭제·추가) 없어진 곡은 버리고 새 곡은 순서 맨 뒤에 붙인다. 값이 손상되면 처음 상태.
- **상태 변경은 저장소 기준**: 단축키 핸들러가 오래된 화면 값을 쥐지 않도록 항상 저장된 최신 값에서 변경한다(`updateQuiz`). 다른 탭에서의 변경도 `storage` 이벤트로 반영된다.
- **게임 초기화(사회자 메뉴)**: `/host`에 K-pop 노래 맞추기 패널(`HostPanel`)을 추가했다. "🔄 게임 초기화"는 공개한 곡을 모두 비우고(원상 복구) 곡 순서를 한 번 섞은 뒤 처음 곡으로 돌아간다. 섞은 결과가 지금 순서와 같으면 앞의 두 곡을 맞바꿔 **반드시 순서가 달라지게** 했다. 클릭 한 번으로 실행하고(확인 단계 없음), 몇 곡을 되돌렸는지 안내한다. 공개 상태는 화면 표시용 상태라 되돌리기 쉬워 확인 단계는 두지 않았다.
- **구조**: 의존 방향(`components/`는 `games/`를 import 하지 않음)을 지키려고 레지스트리 항목에 선택 필드 `HostPanel`을 추가하고, 서버 컴포넌트 `app/host/page.tsx`가 모아 `HostMenu`의 children 으로 넘긴다. 비밀번호를 확인하기 전에는 보이지 않는다. 다른 게임도 같은 방식으로 관리 패널을 붙일 수 있다.
- **순서 섞기(게임 화면 버튼)**: 순서만 바꾸고 이미 공개한 곡은 공개 상태로 둔다(초기화와 구분).
- **같은 기기 전제**: 초기화는 이 기기의 저장소만 지운다. `/host`와 게임을 같은 노트북·브라우저에서 쓴다는 전제이며, 다른 기기의 진행 상태는 건드리지 않는다.

## 2026-11-11 — 정답 공개 시 코러스 15초 자동 재생

### 요청 프롬프트

> "정답 공개" 버튼 클릭하면 코러스 15초 듣기 실행하게 해

### 구현 결정

- 정답 공개 동작(`reveal`)에 코러스 듣기(`playChorus`)를 연결했다. 버튼과 Enter 단축키가 같은 동작이라 **둘 다** 코러스가 재생된다(Enter 만 따로 빼지 않았다).
- **처음 공개할 때만 재생**한다. 이미 공개한 곡에서 Enter 를 다시 눌러도 재생하지 않는다. 곡을 옮기거나 새로고침해도 자동 재생하지 않는다(공개 버튼을 누른 사용자 동작에만 반응). 공개 여부는 단축키 핸들러의 오래된 화면 값 대신 저장소의 최신 값으로 확인한다.

> 공개/미공개 체크박스는 지우고, 아이템의 배경이나 테두리 색으로 공개/미공개를 구분해

### 구현 결정

- 항목 오른쪽의 `✅ 공개` / `⬜ 미공개` 문구를 없앴다. 대신 공개한 문제는 초록 배경·초록 테두리, 공개 전 문제는 회색 배경·회색 테두리로 구분한다.
- 지금 보고 있는 문제는 공개 색을 그대로 둔 채 보라색 고리(`ring`)를 덧씌워 표시한다(공개 색과 겹치지 않게).
- 컨벤션의 "색만으로 정보를 구분하지 않는다"와 어긋나므로, 사용자 요청을 따르되 스크린 리더용 접근 가능한 이름(`N번 제목 정답 공개됨/정답 미공개`)과 `aria-current` 는 그대로 남겼다.

## 2026-11-13 — 노래제목은 공개된 문제만 표시, 칸 너비 14rem으로 복원

### 요청 프롬프트

> 아이템에 노래 제목은 정답이 공개됐을 때만 출력. 그리고 아이템의 칸 너비를 다시 14rem으로 해

### 구현 결정

- 직전 요청("모든 문제에 제목 표시")을 되돌린다. 정답을 공개한 문제는 `번호 + 노래제목`, 공개 전 문제는 번호만 보이고 공개 전 곡의 제목은 DOM 에도 없다. 프로젝터에 정답이 새지 않는 처음 설계로 돌아간 것이다.
- 공개 여부를 배경·테두리 색(공개 = 초록, 미공개 = 회색)으로 구분하는 것은 유지한다. 접근 가능한 이름은 공개 전 `N번 문제 정답 미공개`, 공개 후 `N번 제목 정답 공개됨` 이다.
- 목록 칸의 최소 너비를 `18rem` 에서 `14rem` 으로 되돌렸다.
- "정답 공개 전에는 곡 정보가 화면 어디에도 없다"는 기존 테스트의 엄격한 조건도 원래대로 복원했다.

### 변경 파일

- `games/kpop-quiz/QuestionList.tsx`, `e2e/kpop-quiz.spec.ts`

### 검증

- 아래 `pnpm verify` 결과 참고

## 2026-11-13 — 사회자 메뉴에 정답 미리 보기 추가

### 요청 프롬프트

> 사회자가 정답을 미리 알 수 있도록, 사회자 메뉴에 노래 맞추기의 답을 작성해줘

### 구현 결정

- 사회자 메뉴(`/host`)의 노래 맞추기 패널(`HostPanel`)에 "🤫 정답 미리 보기 (사회자 전용)"을 추가했다. 테마(2000년대·2010년대·CCM·최신가요)마다 접을 수 있는 목록(`<details>`)이며, 열면 `번호 · 곡명 · 가수` 순서로 보인다.
- 번호는 **게임 화면의 문제 번호와 같다.** 저장된 진행 상태의 곡 순서(순서 섞기·초기화 반영)를 그대로 쓰기 때문이다. 이미 정답을 공개한 곡에는 `✅ 공개됨`이 붙는다.
- 처음에는 모두 접혀 있어, 사회자 메뉴를 프로젝터에 띄워도 정답이 바로 보이지 않는다. 안내 문구로 "프로젝터에 비치는 화면에서는 열지 마세요"를 적었다.
- `/host` 는 사회자 비밀번호를 확인한 뒤에만 패널을 렌더하므로 로그인 전에는 곡 정보가 없다(테스트로 확인). 새 API·의존성은 없다.

### 변경 파일

- `games/kpop-quiz/HostPanel.tsx`, `e2e/kpop-quiz.spec.ts`

### 검증

- 아래 `pnpm verify` 결과 참고
