# K-pop 노래 맞추기 (`kpop-quiz`)

## 2026-11-10 — 2008~2010 K-pop 앞부분 듣고 맞추기 (사회자 전용)

### 요청 프롬프트

> # K-pop 노래 맞추기 진행자용 웹 애플리케이션 개발 요청
>
> 2008~2010년 유행했던 K-pop 노래의 앞부분을 듣고 맞추는 레크리에이션 게임을 만들어줘.
>
> ### 1. 주요 요구사항 및 화면 구성
>
> - **진행자(Host) 전용 모드**:
>   - 사회자가 로그인이 되야만 진행할 수 있다.
>   - 진행자가 화면을 띄워두고 프로젝터/모니터 화면 공유나 현장 진행을 할 수 있는 직관적인 단일 대시보드 구조.
> - **블라인드 오디오 재생 (YouTube IFrame Player API)**:
>   - 정답 공개 전에는 참여자들에게 영상 화면, 썸네일, 영상 제목이 노출되지 않도록 화면을 완전히 블라인드(오디오 전용 플레이어 UI) 처리.
>   - 정답 공개 전에는 소리만 출력되어야 함.
> - **구간 듣기 및 오디오 컨트롤**:
>   - 재생, 일시정지, 이전 곡, 다음 곡 이동 버튼.
>   - 문제 출제용 간편 버튼: "앞부분 1초 듣기", "3초 듣기", "전체 재생" 기능 포함.
> - **정답 공개 기능**:
>   - [정답 공개] 버튼 클릭 시 블라인드가 해제되며 가수, 곡명, 앨범 커버 또는 유튜브 실제 영상 화면이 노출됨.
>
> ### 2. 데이터 구조 (Mock Data 포함)
>
> - 2008~2010년 대표 K-pop 5~10곡을 mock data(JSON)로 기본 포함해줘.
>   (예: 소녀시대 - Gee, 빅뱅 - 하루하루, 브라운아이드걸스 - Abracadabra, 2PM - Heartbeat, 원더걸스 - Nobody 등)
> - 데이터 모델 형식: `id`, `title`, `artist`, `youtubeId`, `startTime`(문제 재생 시작 지점, 초 단위, 기본 0초)
>
> ### 3. UI/UX 디자인 가이드
>
> - 어두운 환경(프로젝터 투사 등)에서도 가독성이 높은 모던한 다크 모드 스타일.
> - 직관적인 대형 버튼(재생/정지, 정답 공개)과 키보드 단축키(Space: 재생/정지, Enter: 정답 공개, 방향키: 이전/다음 곡) 지원.

### 구현 결정

- **"로그인" = 사회자 비밀번호**: 프로젝트에 계정 로그인이 없고(규칙 5) 사회자 구분은 `x-host-pin` 비밀번호뿐이라 이를 로그인으로 해석했다. 서버가 비밀번호를 확인한 뒤에만 대시보드를 보여 주고(`useVerifiedHostPin`), 로그인 전에는 곡 정보가 화면에 전혀 없다. 기억해 둔 비밀번호가 바뀌었으면(401) 자동 로그아웃. 비밀번호 폼은 `/host`와 같은 `HostPinForm`을 공용으로 뽑아 재사용했다.
- **서버 상태 없음**: 한 기기(사회자 노트북)에서만 쓰므로 Redis·API 추가 없이 클라이언트에서만 동작한다.
- **YouTube IFrame API**: 요청에 명시된 외부 API로 보고 공식 스크립트를 직접 로드한다(npm 패키지 추가 없음, `youtube.ts`에 최소 타입만 선언). 사회자가 로그인한 뒤에만 스크립트를 불러온다.
- **블라인드**: 플레이어(iframe)를 정상 크기로 두고 불투명 가리개(`blind-cover`)로 완전히 덮는다. 플레이어를 숨기거나 줄이면 재생이 막힐 수 있어서다. 공개 전에는 iframe 영역을 `aria-hidden`으로도 숨긴다. 플레이어 컨트롤·키보드·전체화면·관련 영상은 끈다(`controls=0`, `disablekb=1`, `fs=0`, `rel=0`).
- **정답 공개 시 실제 영상 노출**: 가리개만 치우면 같은 플레이어가 그대로 보인다(앨범 커버 대신 영상 선택).
- **구간 듣기**: 문제 시작 지점(`startTime`)으로 이동·재생한 뒤 `getCurrentTime()`을 50ms마다 확인해 N초에 일시정지한다(타이머로 N초 뒤에 멈추면 버퍼링 지연만큼 짧게 들린다). 전체 재생은 시작 지점부터 끝까지 계속 재생. 곡을 옮기면 자동 재생 없이 새 영상만 준비(cue)한다. 플레이어는 곡마다 새로 만들지 않는다.
- **곡 데이터**: 8곡(소녀시대 Gee, 원더걸스 Nobody, 빅뱅 하루하루, 브라운아이드걸스 Abracadabra, 2PM Heartbeat, 슈퍼주니어 쏘리 쏘리, 샤이니 링딩동, 2NE1 Fire). 영상 ID는 검색으로 찾고 유튜브 oEmbed로 존재·임베드 가능(200)을 확인했다. 링딩동은 공식 오디오 업로드, 하루하루·Abracadabra는 공식 채널이 아닌 업로드라 나중에 삭제될 수 있다. `startTime`은 모두 0으로 두었고 실제 인트로는 듣고 조정이 필요할 수 있다.
- **추가한 것**: 순서 섞기, 로그아웃, 재생 오류(임베드 금지·삭제) 사유 표시.
- **레이아웃**: 큰 화면에서는 무대·정답을 왼쪽, 조작 버튼을 오른쪽에 두어 1920×1080 한 화면에 모두 보이게 했다.
- **범위 밖**: 참여자 휴대폰 화면, 점수판, 서버 저장, 곡 편집 UI(`data/songs.json` 직접 수정).

> 뮤직비디오 말고 노래만 재생되는 유튜브 찾아서 바꿔봐

### 구현 결정

- 8곡의 `youtubeId`를 뮤직비디오에서 **음원 자동 업로드 영상**("Provided to YouTube by …", 채널 `아티스트 - Topic`)으로 교체했다. MV 인트로(로고·연출·멘트) 없이 곡이 바로 시작되고, 정답 공개 때는 앨범 커버가 나온다(요청서의 "앨범 커버 또는 영상" 중 앨범 커버).
- 같은 곡의 라이브·리믹스·재발매 음원이 많아, 각 후보의 영상 설명(앨범·발매일)과 길이를 직접 읽고 2009년 전후 스튜디오 원곡을 골랐다. 전부 oEmbed 로 임베드 가능(200)을 확인했다.

- 코드 변경은 없고 `data/songs.json`과 README 설명만 바꿨다. `startTime`은 그대로 0(음원은 곡이 바로 시작).

## 2026-11-10 — 코러스 구간 재생 버튼 추가

### 요청 프롬프트

> 코러스 구간을 재생하는 버튼 추가

### 구현 결정

- **데이터**: 곡에 선택 필드 `chorusStart`(초)를 추가했다. 값이 없으면 버튼이 꺼진다(`validateSongs`가 음수는 거부).
- **버튼 동작**: "🎤 코러스 15초 듣기"는 코러스 시작 지점으로 이동해 15초(`CHORUS_SECONDS`)만 재생하고 멈춘다. 앞부분 듣기와 같은 구간 재생 코드(`playRange`)를 공유하고, 상태 문구는 "🔊 코러스 구간 듣는 중"으로 구분한다. 곡을 옮기면 그 곡의 코러스 지점을 쓴다.
- **코러스 지점 값은 추정치**: 소리를 직접 들어 확인할 수 없어, 곡 길이가 일치하는 원곡 동기화 가사(LRCLIB 공개 API)에서 **반복되는 6줄 블록의 첫 등장 시점**을 계산하고 0.5초 앞당겼다. 가사 자체는 저장하지 않고 계산된 시간만 데이터에 넣었다. 유튜브 "가장 많이 재생된 장면"과 교차 확인했을 때 Gee(59초)·Nobody(58초)·하루하루(76초)·Heartbeat(74초)는 정점과 겹쳤고, 나머지(Abracadabra 30초·쏘리 쏘리 15초·링딩동 69초·Fire 17초)는 근거가 약하다. 쏘리 쏘리(15초)와 Fire(17초)는 코러스가 아니라 앞부분 후크/프리코러스일 수 있다. 실제 음원과 가사 파일의 길이가 1~2초 어긋나는 곡(Nobody, 링딩동, Fire)은 시점이 그만큼 밀릴 수 있다.
- 단축키는 추가하지 않았다(요청 범위 밖).
