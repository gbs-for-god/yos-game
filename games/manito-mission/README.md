# 마니또 미션

## 진행 흐름

1. 사회자가 노트북에서 `🔒 사회자 확인하고 시작하기` → 비밀번호 입력 → `마니또 게임 시작`을 누르면 모든 사람의 마니또와 미션 3개가 한 번에 정해진다.
2. 참여자는 **자기 휴대폰**으로 같은 주소(사회자 화면에 표시)에 접속해 자기 이름을 누르고 마니또·미션을 확인한다. 노트북 앞에 와서 눌러도 된다.
3. 누가 확인했는지는 모든 기기에 3초 안에 공유된다. 사회자 화면(비밀번호 필요)에서는 전체 배정표를 보고, 필요하면 특정 사람의 미션만 다시 뽑는다.
4. 모임 마지막에 사회자가 `게임 종료하고 공개하기`를 누르면 모든 기기가 공개 화면으로 바뀐다. 사회자 노트북(프로젝터)에서 한 사람씩 `공개!`를 누르면 두구두구 연출 후 마니또가 나오고, 참여자 휴대폰에는 공개된 결과가 따라 나온다.

배정 결과·확인 여부·공개 진행은 서버(Upstash Redis)에 저장되어 어느 기기에서 접속해도 같고, 브라우저를 껐다 켜도 유지된다.
새로 뽑으려면 반드시 사회자 화면의 `전체 다시 뽑기`를 눌러야 한다.

## 파일 구성

| 경로                             | 역할                                                        |
| -------------------------------- | ----------------------------------------------------------- |
| `logic.ts`                       | 배정·상태 전이 순수 함수, 타입                              |
| `server/store.ts`                | Upstash Redis / 메모리 저장소                               |
| `server/handlers.ts`             | 요청 검증 → 상태 전이 → 저장 → 응답 (Route Handler 가 호출) |
| `client.ts`                      | 브라우저 API 호출 + 3초 폴링 훅                             |
| `Game.tsx`                       | 화면 분기 (시작 / 참여자 / 사회자 / 공개)                   |
| `app/api/manito-mission/session` | GET 상태 · POST 동작 · DELETE 초기화                        |

## 데이터·환경 변수

| 항목                                    | 내용                                                                              |
| --------------------------------------- | --------------------------------------------------------------------------------- |
| `data/members.json`                     | `host`(사회자 이름), `participants`(참여자 이름 배열), `hostPin`(비밀번호 기본값) |
| `data/missions.json`                    | 미션 목록. `id`는 겹치지 않게, 최소 3개 이상 유지                                 |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | Vercel Marketplace 의 Upstash Redis 연동이 자동 주입. 없으면 서버 메모리에 저장   |
| `MANITO_HOST_PIN`                       | 사회자 비밀번호. 운영 환경에서는 이 변수로 설정해 `members.json` 값을 덮어쓸 것   |

명단을 바꾼 뒤에는 사회자 화면에 경고가 뜨며, `전체 다시 뽑기`로 새 명단을 적용한다.
