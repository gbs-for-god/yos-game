# 마니또 미션

## 진행 흐름

1. 참여자는 **자기 휴대폰**으로 사이트에 접속해 `/join`에서 자기 이름을 등록한다 (사이트 공용, 한 번만). 사회자 화면에 등록 주소가 표시된다.
2. 사회자가 노트북에서 `🔒 사회자 확인하고 시작하기` → 비밀번호 → `마니또 게임 시작`을 누르면 모든 사람의 마니또와 미션 3개가 한 번에 정해진다. 미션은 사람마다 전체 20개 중 서로 다른 3개를 독립적으로 뽑으므로(`pickMissions`), 한 사람 안에서는 중복이 없지만 다른 사람과는 같은 미션이 나올 수 있다. 사회자의 "미션 다시 뽑기"는 같은 방식으로 뽑되 그 사람이 이전에 받은 미션은 제외한다.
3. 등록된 참여자는 게임 화면에서 `내 마니또 뽑기!`를 눌러 자기 결과를 본다. 서버가 기기 토큰으로 본인을 확인하므로 남의 결과는 볼 수 없다. 화면을 껐다 켜거나 재접속해도 같은 결과가 나온다.
4. 누가 확인했는지는 모든 기기에 10초 안에 공유된다. 사회자 화면(비밀번호)에서는 전체 배정표·기기 등록 여부를 보고, 특정 사람의 미션만 다시 뽑거나 기기 등록을 초기화할 수 있다.
5. 모임 마지막에 사회자가 `게임 종료하고 공개하기`를 누르면 모든 기기가 공개 화면으로 바뀐다. 사회자 노트북(프로젝터)에서 한 사람씩 `공개!`를 누르면 두구두구 연출 후 마니또가 나오고, 참여자 휴대폰에는 공개된 결과가 따라 나온다.

배정·확인 여부·공개 진행·참여자 등록은 서버(Upstash Redis)에 저장되어 어느 기기에서 접속해도 같고, 브라우저를 껐다 켜도 유지된다.
새로 뽑으려면 반드시 사회자 화면의 `전체 다시 뽑기`를 눌러야 한다.

## 파일 구성

| 경로                             | 역할                                                        |
| -------------------------------- | ----------------------------------------------------------- |
| `logic.ts`                       | 배정·상태 전이 순수 함수, 타입                              |
| `server/store.ts`                | 세션·확인 기록 저장소 (Redis / 메모리)                      |
| `server/handlers.ts`             | 요청 검증 → 상태 전이 → 저장 → 응답 (Route Handler 가 호출) |
| `client.ts`                      | 브라우저 API 호출 + 폴링 훅 (평소 10초, 공개 단계 5초)      |
| `Game.tsx`                       | 화면 분기 (시작 / 등록 안내 / 참여자 / 사회자 / 공개)       |
| `app/api/manito-mission/session` | GET 상태 · POST 동작 · DELETE 초기화                        |

참가자 등록은 사이트 공용 계층(`lib/participants`)을 쓴다. **게임 멤버는 사회자가 시작(또는 전체 다시 뽑기)을 누른 순간 등록되어 있는 참가자 전체**이고, 시작한 기기의 이름은 공개 순서 맨 마지막(사회자)이 된다. 나머지는 가나다순이다. 최소 2명이 필요하다.

## 데이터·환경 변수

| 항목                                    | 내용                                                                            |
| --------------------------------------- | ------------------------------------------------------------------------------- |
| `data/missions.json`                    | 미션 목록. `id`는 겹치지 않게, 최소 3개 이상 유지                               |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | Vercel Marketplace 의 Upstash Redis 연동이 자동 주입. 없으면 서버 메모리에 저장 |
| `HOST_PIN`                              | 사회자 비밀번호. 없으면 기본값 `0000`. 운영 환경에서는 반드시 설정할 것         |

게임 시작 뒤에 새로 등록하거나 해제된 사람이 있으면 사회자 화면에 경고가 뜨고, 그 사람은 배정이 없다는 안내를 받는다. `전체 다시 뽑기`로 지금 등록된 사람들을 다시 반영한다.
